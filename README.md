## Запуск в Docker

Шесть сервисов из `docker-compose.yml`: `postgres`, `redis`, `rabbitmq`, `api`, `worker` (тот же образ, что `api`, разбирает очередь и отправляет письма), `web`. Наружу открыт только порт витрины `3001`. Сервер Temporal и его воркер в compose не входят и запускаются отдельно.

1. Значения переменных:

   ```bash
   cp .env.example .env   # заполнить; .env в репозиторий не попадает
   ```

2. База, кеш и брокер:

   ```bash
   docker compose up -d postgres redis rabbitmq
   ```

3. Данные. Сидов пока нет, поэтому база в контейнере заполняется копией локальной (локальная база только читается):

   ```bash
   pg_dump --no-owner --no-privileges "<DATABASE_URL локальной базы>" \
     | docker compose exec -T postgres sh -c 'psql -q -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
   ```

4. `api` и `worker`:

   ```bash
   docker compose build api
   docker compose up -d api worker
   ```

5. Образ витрины. Сборка заранее рендерит страницы и обращается к API, а шаги сборки не видят сеть compose. Поэтому на время сборки поднимается временный `api` с портом `3000` на машине:

   ```bash
   docker compose run -d --rm --no-deps --name realty-api-build -p 3000:3000 api
   docker compose build web
   docker rm -f realty-api-build
   ```

6. Всё вместе:

   ```bash
   docker compose up -d
   ```

   Витрина: <http://localhost:3001>. Журнал одного сервиса: `docker compose logs -f worker`.

## Требования к окружению

### Поиск секретов (gitleaks)

Хук `pre-commit` проверяет индексированные изменения через [gitleaks](https://github.com/gitleaks/gitleaks) и не даёт закоммитить ключи, токены и пароли. Без установленного `gitleaks` коммит не пройдёт:

```bash
brew install gitleaks
```

Та же проверка по всей истории запускается в CI. Ложные срабатывания после проверки вносятся в `.gitleaks.toml`, хук не отключается.

### Service Worker

`Service Worker` работает только с `HTTPS`. Исключение - `localhost`.
В production нужно использовать `HTTPS`, без него SW не зарегистрируется, а фотографии не смогут загружаться через посредник с заголовком `Authorization`.

#### 5. Количество запросов, попавших в очередь

Всего в первой волне: 1 (`refresh`), потом 5, потом 15 запросов.
Лимит параллельности браузера (`HTTP/1.1`): 6 запросов.
Встали в очередь: 15 − 6 = 9 запросов.

![Скриншот](README_screenshots/Release-2_7.webp)

Вывод: При переключении на вкладку `All` видно, что в самую первую секунду загрузки страницы приложение одновременно инициирует 15 запросов. Лимит `HTTP/1.1` — не более 6 одновременных соединений на один домен. В результате первые 6 запросов начали выполняться сразу, а остальные 9 запросов встали в очередь. По мере парсинга страницы общее число запросов увеличилось до 81. В реальных проектах эту проблему решают переходом на протокол `HTTP/2` или `HTTP/3`, где этого лимита в 6 запросов нет, и все 15 запросов выполняются одновременно. Так что, вроде бы, оптимизировать нечего.

#### 2. Причины рендеров компонентов

Самый дорогой компонент `ListingFilterPanel` перерисовывается по причине `Hook changed: State (Hook 1)` (ввод символов) и `Hook changed: DebouncedValue (Hook 2)` (срабатывание дебаунса задержки).

Объявления `ListingListItem` перерисовываются по причине `The parent component rendered`. Они перерисовываются вслед за родителем.

`ListingsSection` перерисовывается по причине `Hooks 15 and 16 changed` - обновление стейта списка объявлений после получения ответа бэкенда.

#### 3. Подсветка перерисованных областей на странице

При вводе букв (в процессе) подсвечиваются `ListingFilterPanel` и `Link` на карточках объявлений.

После завершения ввода (срабатывание дебаунса и ответ сервера) подсвечиваются `ListingsSection`, `Layout`, `Link` в навигации шапки и `Link` на карточках объявлений. Меняется контекст роутера в URL и приходят новые данные с бэкенда, заставляя перерисоваться всю секцию.

#### 4. Тест с React Compiler (Сравнение двух записей)

1. В обоих режимах (с компилятором и без) зафиксировано 8 коммитов. На вкладке `Ranked` самыми дорогими компонентами так же, как и с компилятором, являются `ListingFilterPanel` и `ListingsSection`.

2. `ListingFilterPanel` перерисовывается на коммитах 1, 3, 4 по причине `Hook changed: State (Hook 1)` (ввод символов), на коммите 5 — по причине `Hook changed: DebouncedValue`, а на коммитах 6, 7 и 8 — по причине `Props changed`.
   Объявления `ListingListItem` всё так же перерисовываются по причине `The parent component rendered`. Они перерисовываются вслед за родителем.

3. Подсветка не меняется, как и её причины.
